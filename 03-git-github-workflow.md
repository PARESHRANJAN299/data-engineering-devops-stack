# Phase 3 — Git + GitHub Workflow
test-main-protection
## Phase Goal
Establish a reliable Git and GitHub workflow for version control, collaboration, and project tracking on the remote environment.

## Step 1: Initialize repository workflow
- Confirm repo structure.
- Review branch strategy.
- Ensure remote access is configured properly.

## Step 2: Commit and push changes
- Make updates from the EC2 remote environment.
- Stage files and create meaningful commit messages.
- Push to the GitHub repository.

## Step 3: Validate repo flow
- Check status, branches, and remote configuration.
- Reconnect to GitHub cleanly.
- Confirm the repo is ready for future work.

This phase demonstrates the manual feature-branch, commit, push, pull-request, approval, and merge workflow.

## Issues faced
- Repository tracking was not fully structured at the start.
- Local and remote changes needed clear ownership.
- Commit history needed consistent naming and tracking.

## Root cause
- The repo was still being shaped while the project was evolving.
- There was no clear convention for documenting project phases and updates.
- No single flow existed for tracking remote edits systematically.

## Fix
- Standardize branch and commit practices.
- Keep a central project tracker in the repository root.
- Document new phases as separate Markdown files.
- Use the GitHub repo as the source of truth for project updates.

## What I learned
- Git keeps project history transparent and auditable.
- Clear commit messages make troubleshooting easier.
- Repository structure matters when a project grows across phases.
- GitHub is the foundation for collaboration and automation.
